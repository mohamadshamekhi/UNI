# راهنمای استقرار — فاز ۱

مخاطب: تیم فنی و DevOps دانشگاه. Dockerfile و خط CI/CD در پایان فاز ۱ اضافه می‌شوند؛ این راهنما اجزا، پیکربندی و الزامات را مشخص می‌کند.

## ۱. اجزا

| جزء | فناوری | پورت پیش‌فرض | توضیح |
|---|---|---|---|
| API | Node.js 24، NestJS 12 | 4000 | `apps/api`؛ OpenAPI در `/docs` (غیر production) و `/health` |
| پنل وب (دانشجو/استاد) | Next.js 16 | 3000 | `apps/web`؛ هر دانشگاه روی `<slug>.<TENANT_BASE_DOMAIN>` |
| بک‌آفیس | Next.js 16 | 3001 | `apps/backoffice` |
| پایگاه داده | PostgreSQL 17 | 5432 | جداسازی سازمان‌ها با RLS |
| صف و کش | Redis 7 | 6379 | محدودیت نرخ، نشست‌ها، صف اسکن فایل |
| فضای فایل | S3 سازگار (MinIO) | 9000 | سطل خصوصی؛ رمزنگاری در سطح دیسک/سطل |
| ضدبدافزار | ClamAV (clamd) | 3310 | `clamav/clamav-debian` (چندمعماری) |

مرورگر فقط با Next صحبت می‌کند؛ توکن‌ها در کوکی httpOnly هستند و Next درخواست‌ها را به `API_URL` می‌فرستد.

## ۲. پایگاه داده و نقش‌ها

سه نقش PostgreSQL لازم است (`infra/postgres/init.sql`):

| نقش | کاربرد | ویژگی |
|---|---|---|
| `uni_owner` | اجرای migration، مالک اسکیما | فقط در زمان استقرار |
| `uni_app` | ترافیک درخواست‌ها | **بدون** BYPASSRLS؛ همه داده‌های سازمانی با RLS محافظت می‌شوند |
| `uni_system` | کارهای پس‌زمینه و خواندن‌های بین‌سازمانی صریح | BYPASSRLS؛ رمز جداگانه |

جدول ممیزی فقط افزودنی است (REVOKE + trigger) و زنجیره هش دارد.

```bash
pnpm --filter @uni/api build
DATABASE_OWNER_URL=... pnpm --filter @uni/api db:migrate   # migrations/*.sql به ترتیب؛ تغییر فایل اعمال‌شده خطا می‌دهد
pnpm --filter @uni/api db:seed                              # مدیر کل اولیه از SEED_PLATFORM_ADMIN_*
```

## ۳. متغیرهای محیطی API

| متغیر | الزامی | توضیح |
|---|---|---|
| `NODE_ENV` | ✓ | `production` |
| `DATABASE_URL` / `DATABASE_SYSTEM_URL` / `DATABASE_OWNER_URL` | ✓ | اتصال با سه نقش بالا |
| `REDIS_URL` | ✓ | |
| `JWT_ACCESS_SECRET`، `JWT_PROOF_SECRET`، `FILE_TOKEN_SECRET`، `HASH_PEPPER` | ✓ | هر کدام تصادفی و حداقل ۳۲ کاراکتر |
| `DATA_ENC_KEY` | ✓ | رمزنگاری کلیدهای ورود دومرحله‌ای؛ **از دست رفتن یا تغییر آن، ورود دومرحله‌ای همه را از کار می‌اندازد — پشتیبان بگیرید** |
| `S3_ENDPOINT`، `S3_REGION`، `S3_ACCESS_KEY`، `S3_SECRET_KEY`، `S3_BUCKET` | ✓ | |
| `FILE_SCAN_MODE` | ✓ | در production فقط `clamav` (مقدار `skip` رد می‌شود) |
| `CLAMAV_HOST`، `CLAMAV_PORT` | ✓ | |
| `TENANT_BASE_DOMAIN` | ✓ | مثلاً `uni.example.ir` |
| `CORS_ORIGINS` | | فقط در صورت فراخوانی مستقیم API از مرورگر |
| `OTP_IP_LIMIT_PER_HOUR`، `LOGIN_IP_LIMIT_PER_15MIN` | | در شبکه‌های پردانشجو با NAT مشترک افزایش دهید |
| `MAINTENANCE` | | `off` کار نگهداری ساعتی را روی آن نمونه خاموش می‌کند |
| `SMS_PROVIDER` | | فعلاً `console`؛ آداپتور سرویس پیامک دانشگاه اضافه می‌شود |

پنل‌ها: `API_URL` (نشانی داخلی API)، و در پنل وب `TENANT_BASE_DOMAIN` و `NEXT_PUBLIC_BACKOFFICE_URL` (هنگام build).

## ۴. شبکه و پروکسی معکوس

- **HTTPS اجباری** (کوکی‌ها در production `secure` هستند). TLS 1.2 به بالا.
- **DNS و گواهی wildcard** برای `*.TENANT_BASE_DOMAIN`؛ دامنه اختصاصی هر دانشگاه هم باید به پنل وب برسد.
- پروکسی جلوی Next باید `X-Forwarded-For` را با IP واقعی کاربر **بازنویسی** کند؛ محدودیت‌های نرخ کد پیامکی و ورود بر اساس IP است. مقدار `trust proxy` در `apps/api/src/bootstrap.ts` باید با تعداد پروکسی‌ها یکی باشد.
- API و پایگاه داده نباید از اینترنت مستقیم در دسترس باشند.
- حجم درخواست: حداکثر ۵ مگابایت برای مدارک و ۲ مگابایت برای فایل ورود گروهی.

## ۵. کارهای پس‌زمینه

- **اسکن فایل:** صف BullMQ داخل API؛ فایل تا پاک بودن نتیجه اسکن قابل دانلود نیست.
- **صف اعلان (outbox):** هر ۲ ثانیه؛ ارسال پیامک تصمیم‌ها.
- **نگهداری ساعتی:** حذف مدارک طبق سیاست هر دانشگاه، پاک‌سازی فضای ذخیره پس از ۷ روز، حذف کدهای یکبارمصرف قدیمی، نشست‌های قدیمی‌تر از ۹۰ روز و رویدادهای ارسال‌شده. با قفل پایگاه داده روی چند نمونه همزمان فقط یک بار اجرا می‌شود. رکوردهای ممیزی هرگز حذف نمی‌شوند.

## ۶. پشتیبان‌گیری و بازیابی (پیشنهاد سند، نیازمند تأیید)

| مورد | سیاست |
|---|---|
| PostgreSQL | پشتیبان کامل روزانه + بایگانی WAL برای بازیابی تا لحظه (PITR) |
| فایل‌ها | همانندسازی سطل به محل دوم |
| نگهداری | ۳۰ روز روزانه، ۱۲ ماه ماهانه |
| هدف | RPO ≤ ۱۵ دقیقه، RTO ≤ ۴ ساعت؛ تمرین بازیابی فصلی |
| اسرار | `DATA_ENC_KEY` و سایر کلیدها در مخزن اسرار با پشتیبان جداگانه |

## ۷. پایش

- `GET /health` وضعیت پایگاه داده و Redis را برمی‌گرداند.
- لاگ‌ها JSON ساخت‌یافته با `requestId` هستند (هدر `x-request-id` در پاسخ‌ها)؛ اطلاعات حساس ماسک می‌شوند.
- هشدار پیشنهادی: نرخ خطای ۵xx، طول صف اسکن، شکست‌های outbox، پر بودن دیسک، انقضای گواهی TLS.
